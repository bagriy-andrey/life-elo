# 09 — Profile redesign

Status: approved
Design input: `docs/design/profile/Profile.dc.html` + `docs/design/profile/README.md` (Claude Design export; the plan wins over the mockup; mockup numbers/dates/version are placeholders for real data)

## Why
The Profile tab is a long stack: head, avatar, tiles, rows, then separate Account and Settings blocks with big full-width buttons.
The redesign groups it into view/edit modes: centered identity, two stat tiles, sections Аккаунт / Настройки / Данные with list rows,
a language bottom sheet, full-width «Сменить пароль» / «Выйти», and an app-version footer. Mostly layout/UX reusing existing logic
(validation, photo, clear-all, sync, password, logout), plus three additions: JSON export (with a derived rating block), login-email change,
and a per-plan app version. No scoring change; rating stays derived (replay) and is only displayed/exported.

## User decisions (2026-11-08)
- **Version**: the app version changes on every plan built by agents. This plan sets `package.json` to `0.9.0` (minor = plan number); the `__APP_VERSION__` Vite define stays. Rule (added to the build-plan skill and AGENTS.md): when the last step of plan NN is checked and verified, bump `package.json` (+ `package-lock.json`) to `0.NN.0` and commit `chore: version 0.NN.0`; fix rounds within a plan bump the patch (`0.NN.1`, …).
- **Export includes the rating**, alongside the raw synced records: a derived `rating` block computed with the engine `replay` over confirmed reviews (current rating + per-day history `{ day, delta, rating }`), labelled in the payload as derived and not imported back. It is not stored anywhere, so "rating is never stored" holds.
- **Profile `email` field stays** in the edit form as today (validation + saved).
- **Login email can be changed** from Аккаунт («Почта для входа» row, «Сменить») for email/password accounts via `supabase.auth.updateUser({ email })`, with the Notice «Мы отправили письмо для подтверждения на новый адрес» (Supabase secure email change). Google-only accounts see the email with the caption «Вход через Google» and no action.

## Defaults chosen by the planner (change on review)
- **Edit mode shows only the form** (as in the mockup): no Account/Settings/Data sections while editing. Profile `email` stays in the form (user decision), after Ник.
- **View mode** shows the profile `email` (if set) as a muted line under the birth line; the login email is in Аккаунт.
- **«С нами с»** = `profile.createdAt` (already the case).
- **Sync status**: dot green for `idle` with `lastSyncedAt`, red for `error`/`update-required`, grey for `syncing`/`offline`/never-synced. ↻ = `engine.resync()`, disabled and spinning while `syncing`. The separate «Повторить» button is dropped.
- **Export file** `life-elo-export.json`: `{ app, version, exportedAt, data: { <SYNCED_TABLES>: rows[] }, rating: { derived: true, note, current, history: [{ day, delta, rating }] } }`. Includes the profile photo data URL. Delivery: `navigator.share({ files })` when `canShare` accepts a file (iOS standalone PWAs often ignore `<a download>`), else `<a download>` blob link. Row hint «JSON», then «Файл сохранён».
- **Clear-all dialog text** gets «Перед этим можно сделать экспорт.» (`settings.clearBody`, 3 languages). Behavior unchanged.
- **Email-change template**: `supabase/templates/email_change.html` uses `{{ .ConfirmationURL }}` (standard link), not the token-hash custom link used for recovery; the user pastes it into Supabase like `recovery.html` (documented in `docs/setup/backend.md`). Known limit: on iPhone the link opens in Safari; the change is confirmed server-side and the installed app sees the new email on its next session refresh. With Supabase «Secure email change» on, confirmation may be requested from both old and new addresses; the Notice text covers only the new one.
- **Change-email action** is offered when the user has an `email` identity (`canChangeLoginEmail`); Google identity only (even if a password was set) => caption «Вход через Google», no action.
- First run (no profile yet): edit form without «Отмена», plus «Выйти»; no other sections.
- Language/theme stay per device (localStorage), not synced.

## Acceptance criteria
- WHEN a profile with a name exists THE app SHALL open Profile in view mode: avatar 88px, name, `@nick` (if any), birth line «date · age» (if any), profile email (if any), and «Изменить».
- THE view SHALL show tiles «Рейтинг» (signed, colored by sign, from replay, 1 decimal) and «С нами с» (long date of `createdAt` in the UI locale).
- THE view SHALL show sections Аккаунт (login email; sync dot + label + round ↻ button), Настройки (Язык row with current language and ›; Тема SegmentedControl), Данные (Экспорт row with hint; red «Очистить все данные» row with caption), then full-width «Сменить пароль» (or «Задать пароль» for Google-only) and «Выйти», then «Life Elo · версия X.Y.Z» (`0.9.0` after this plan).
- WHEN the account has an email identity THE «Почта для входа» row SHALL offer «Сменить»; it opens a dialog with a new-email field (validated with the auth email rule, must differ from the current email); on submit THE app SHALL call `supabase.auth.updateUser({ email })` and show the Notice «Мы отправили письмо для подтверждения на новый адрес»; failures show the text from `authErrorText`; the login email shown is not changed until confirmed.
- WHEN the account is Google-only THE row SHALL show the email with the caption «Вход через Google» and no «Сменить».
- WHEN the Язык row is tapped THE app SHALL open a bottom sheet with the 3 languages, ✓ on the current one; picking applies immediately and closes; Esc/overlay tap closes.
- WHEN ↻ is tapped THE app SHALL run `engine.resync()`; the button is disabled and spinning while `syncing`.
- WHEN «Экспорт данных» is tapped THE app SHALL deliver `life-elo-export.json` with the raw records and a derived `rating` block (current + per-day history, flagged as derived) and show «Файл сохранён»; cancelling the share sheet shows nothing; failure shows an error Notice. Importing/sync never reads the `rating` block.
- WHEN «Очистить все данные» is tapped THE app SHALL open the confirm Dialog; confirming wipes server + device as before; failure shows the existing error text.
- WHEN logging out with unsynced changes THE app SHALL still show the existing confirm before signing out.
- WHEN «Изменить» is tapped THE app SHALL show only the edit form: avatar picker with add/change/remove photo, Имя (required), Ник (optional, `@`), Почта (optional, validated), Дата рождения (optional, age hint + «Убрать»), «Сохранить», «Отмена» in the header (discarding the draft). Validation rules and timing are unchanged.
- WHEN there is no profile THE app SHALL show the edit form without «Отмена», plus «Выйти».
- WHEN the last step of a plan is verified THE build-plan flow SHALL bump the version to `0.NN.0` (patch for fix rounds) and commit `chore: version 0.NN.0`.
- All new texts exist in ru/en/uk. No horizontal overflow at 375px; every tappable row/button ≥44px high.
