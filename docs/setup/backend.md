# Настройка бэкенда Life Elo с нуля

Чек-лист для того, у кого пока нет ни одного аккаунта. Делайте по порядку. Названия кнопок и разделов в
панелях сервисов иногда меняются, поэтому ищите пункты по смыслу. Если чего-то нет на своём месте, используйте
поиск по панели или документацию сервиса.

Что получится: приложение на `*.vercel.app`, аккаунты (почта + пароль, Google), восстановление пароля письмом
с вашего домена, синхронизация данных между устройствами.

Важно: ключи и пароли не коммитим. Файл `.env` в git не попадает (см. `.gitignore`), в репозитории лежит только `.env.example`.

## 0. Домен

Домен нужен только как адрес отправителя писем (`no-reply@ваш-домен`). Само приложение работает на
`*.vercel.app`, и домен для него не нужен.

1. Зарегистрируйтесь в Cloudflare (Registrar) или Porkbun, подтвердите почту, включите двухфакторную защиту.
2. Найдите свободное имя через поиск доменов и купите его (обычно хватает самой дешёвой зоны, например `.com`
   или `.app`). Включите автопродление.
3. Запишите домен, ниже он обозначен как `DOMAIN`.

Пока Resend не готов (шаг 5), встроенная почта Supabase отправляет письма на адрес владельца проекта. Для
тестирования этого достаточно.

## 1. Supabase: проект

1. Зарегистрируйтесь на supabase.com (можно через GitHub или почту).
2. Создайте организацию, если её попросят, затем новый проект (New project).
3. Заполните имя (например `life-elo`), придумайте пароль базы данных и сохраните его в менеджере паролей.
4. Регион: Frankfurt (eu-central-1), ближайший к Европе. Тариф: Free.
5. Дождитесь создания проекта.
6. Откройте настройки проекта, раздел API. Скопируйте:
   - Project URL, это будет `VITE_SUPABASE_URL`;
   - publishable key (ключ вида `sb_publishable_...`), это будет `VITE_SUPABASE_PUBLISHABLE_KEY`.
   Секретный ключ (secret / service_role) не копируйте и никуда не вставляйте.
7. Локально: скопируйте `.env.example` в `.env.local` и подставьте оба значения. Эти же две переменные позже
   добавляются в Vercel (шаг 7).
8. Запомните также Project Reference (идентификатор проекта, часть адреса `https://<ref>.supabase.co`), он
   понадобится для `supabase link`.

## 2. Supabase: настройки авторизации

Раздел Authentication в панели проекта. Адрес Vercel появится на шаге 7, поэтому к пунктам про Site URL
вернитесь после него (сначала можно поставить `http://localhost:5173`).

1. Провайдер Email включён. Подтверждение почты (Confirm email) ВЫКЛЮЧЕНО: пользователь входит сразу после регистрации.
2. Срок действия одноразовых ссылок и кодов (OTP expiry): 3600 секунд.
3. Политика паролей: минимальная длина 8, обязательны буквы и цифры. В панели это настройки пароля
   (минимальная длина и требуемые символы, например вариант «буквы и цифры» / letters and digits); название пункта
   может отличаться, ищите по смыслу.
4. URL Configuration:
   - Site URL: адрес приложения на Vercel (`https://....vercel.app`);
   - Redirect URLs (список разрешённых): адрес Vercel и `http://localhost:5173`.

## 3. Google Cloud: вход через Google

1. Зайдите на console.cloud.google.com под своим Google-аккаунтом, согласитесь с условиями.
2. Создайте проект (например `life-elo`) и выберите его.
3. Настройте экран согласия OAuth (раздел Google Auth Platform / OAuth consent screen): название приложения,
   ваша почта поддержки, тип аудитории External, контактная почта разработчика. Запрашиваются только базовые
   данные (email, профиль), дополнительных областей не нужно.
4. Если приложение остаётся в режиме Testing, добавьте свой адрес в список тестовых пользователей. Либо
   опубликуйте приложение (In production): для базовых областей проверка Google обычно не требуется.
5. Создайте учётные данные: OAuth client ID, тип Web application. В Authorized redirect URIs добавьте
   Callback URL из Supabase (Authentication, Providers, Google, там он показан; вид
   `https://<ref>.supabase.co/auth/v1/callback`).
6. Скопируйте Client ID и Client secret.
7. В Supabase: Authentication, Providers, Google. Включите провайдер, вставьте Client ID и Client secret, сохраните.

## 4. Resend: письма с вашего домена

Без своего SMTP Supabase (бесплатный план) не даёт править шаблоны писем (раздел 5), а стандартная ссылка сброса
нашему приложению не подходит. Поэтому SMTP нужен до проверки сброса пароля.

**Без домена (для проверки):** пропустите шаги 2–4, в шаге 6 укажите Sender email `onboarding@resend.dev`.
Такие письма Resend доставляет только на почту, с которой вы зарегистрированы в Resend, — регистрируйтесь той,
которой входите в Life Elo. Когда появится домен, пройдите шаги 2–4 и поменяйте только Sender email.

1. Зарегистрируйтесь на resend.com.
2. Раздел Domains, добавьте `DOMAIN` (регион можно выбрать Europe, если есть).
3. Resend покажет DNS-записи (обычно SPF и DKIM, иногда MX). Добавьте их у регистратора домена, в DNS-настройках
   (Cloudflare: DNS, Records; Porkbun: DNS). Значения копируйте точно как в Resend. Если у регистратора есть
   прокси (оранжевое облако Cloudflare), для этих записей он должен быть выключен (только DNS).
4. Нажмите Verify в Resend и дождитесь статуса Verified (от минут до нескольких часов).
5. Раздел API Keys, создайте ключ с правом отправки, скопируйте его (показывается один раз).
6. В Supabase: Authentication, настройки SMTP (Custom SMTP), включите и заполните:
   - Host: `smtp.resend.com`, порт: `465` (или `587`, как указано в документации Resend);
   - Username: `resend`, Password: ключ API из Resend;
   - Sender email: `no-reply@DOMAIN`, Sender name: `Life Elo`.
   Сохраните.

## 5. Шаблон письма восстановления пароля

Требует настроенного SMTP (раздел 4): без него поля шаблона в Supabase недоступны для редактирования.

1. Authentication, Emails, Templates, шаблон Reset Password. Body правьте в режиме Source.
2. Тема: `Восстановление пароля Life Elo`.
3. Тело: вставьте содержимое файла `supabase/templates/recovery.html` . Ссылка в нём
   ведёт на `{{ .SiteURL }}/?type=recovery&token_hash={{ .TokenHash }}`. Это сделано намеренно: на iPhone ссылка из
   письма открывается в Safari, а не в установленном приложении, и стандартная PKCE-ссылка не сработала бы.
4. Сохраните.

## 6. Схема базы (миграции)

В корне репозитория, после установки зависимостей (`npm install`):

1. `npx supabase login` (откроется браузер для входа).
2. `npx supabase link --project-ref <ref>` (введите пароль базы из шага 1).
3. `npx supabase db push --remote` применит файлы из `supabase/migrations/` к облачному проекту (без `--remote` CLI ищет локальную базу в Docker и падает с ECONNREFUSED 127.0.0.1:54322).

Повторяйте `db push --remote` после каждого нового файла миграции. Сейчас таких файлов три (вторая, `*_records_profile.sql`, включает синхронизацию профиля; третья, `*_reset_tombstones.sql`, делает сброс данных видимым для других устройств): если вы уже применяли предыдущие миграции, снова выполните `npx supabase db push --remote`.

## 7. Vercel: деплой

1. Зарегистрируйтесь на vercel.com (удобнее всего через GitHub, тариф Hobby).
2. Add New, Project: импортируйте репозиторий с приложением, предоставив Vercel доступ к нему.
3. Framework Preset: Vite (определяется автоматически); build command `npm run build`, output directory `dist`.
4. До первого деплоя добавьте переменные окружения (Environment Variables) для Production и Preview:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_PUBLISHABLE_KEY`
5. Deploy. Скопируйте итоговый адрес `https://....vercel.app`.
6. Вернитесь к шагу 2 и укажите этот адрес в Site URL и в списке Redirect URLs. Если Vercel выдал другой адрес,
   чем вы ожидали, обновите оба значения.
7. Переменные `VITE_*` вшиваются при сборке: после добавления или изменения любой из них обязательно сделайте
   Redeploy (Deployments, три точки, Redeploy), иначе приложение соберётся без ключей.
8. Site URL и Redirect URLs в Supabase (Authentication, URL Configuration) должны содержать итоговый адрес Vercel
   (и `http://localhost:5173` для разработки), иначе ссылка восстановления и вход через Google не вернут в приложение.

## 8. Проверка

Ручной чек-лист (отмечайте по мере прохождения; о сбоях в iPhone PWA сообщайте, не обходите молча).

- [ ] Регистрация: имя, почта, пароль. Приложение открывается сразу, без письма.
- [ ] Вход: верные данные пускают; неверный пароль и несуществующая почта дают «Неверная почта или пароль».
- [ ] Google: вход на десктопе (Safari/Chrome).
- [ ] Google: вход в установленном PWA на iPhone (если не работает, зафиксируйте, как именно).
- [ ] Забыли пароль: одинаковый текст успеха для существующей и несуществующей почты; письмо от
      `Life Elo <no-reply@DOMAIN>` на русском, ссылка действует 1 час.
- [ ] Ссылка из письма открывается в Safari (отдельно от PWA): задаёте новый пароль, затем входите в приложении.
      Старый пароль не подходит, новый подходит.
- [ ] Смена пароля: с неверным текущим «Текущий пароль указан неверно»; с верным пароль сохранён, на других
      устройствах сессия завершена.
- [ ] Вход только через Google: в настройках пароля «Задать пароль» без поля текущего пароля.
- [ ] Два устройства: изменение на A появляется на B после следующей синхронизации, рейтинг на обоих одинаковый.
- [ ] Офлайн: правки без сети работают, после подключения уходят в облако; при конфликте побеждает более поздняя.
- [ ] Первый вход с локальными данными в пустой аккаунт: данные загружаются в облако.
- [ ] Данные есть и локально, и в облаке: приложение спрашивает, какую копию оставить.
- [ ] Выход: на устройстве не остаётся данных аккаунта (IndexedDB пуста).
- [ ] RLS: войдите вторым аккаунтом. Он не видит данных первого. Дополнительно в SQL editor Supabase
      (uuid второго аккаунта — в Authentication → Users):
      ```sql
      begin;
      set local role authenticated;
      set local request.jwt.claims = '{"sub":"<uuid второго аккаунта>","role":"authenticated"}';
      select count(*) as visible,
             count(*) filter (where user_id <> '<uuid второго аккаунта>') as foreign_rows
      from public.records;
      rollback;
      ```
      `foreign_rows` должно быть 0.
- [ ] Установка на iPhone: Safari, Поделиться, На экран «Домой».
